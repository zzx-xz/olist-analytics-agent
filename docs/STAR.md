# 面试 STAR 讲述稿

下面的 STAR 结构使用项目目前已经实现的内容和当前评估报告。量化评估包含 19 条自建问题的一轮回归；面试时应说明匹配口径和样本规模。

## S：背景

Olist 项目有 9 张相互关联的业务表和近 10 万笔订单。Power BI 看板能展示固定分析主题；回答新的临时问题，仍要人工确认指标口径、关联多张表并编写 SQL。

## T：任务

实现一个经营分析 Agent，让用户用自然语言提出问题，并获得可追溯的数据结论；同时控制模型对本地分析库的访问范围，避免错误查询和无法复核的数字。

## A：行动

1. 将 9 张原始 CSV 流式导入本地 SQLite；统一多种日期文本格式，并为常用关联字段建立索引。
2. 将 GMV、复购率、延迟率和差评率整理成结构化指标目录，明确字段、分子分母和适用范围；记录 payments、order_items 的订单粒度关系，避免不必要关联导致漏单或重复计数。
3. 使用 DeepSeek Tool Calling 编排指标查询、表结构发现和 SQL 执行；将失败信息反馈给模型，并限制 Agent 最多运行 8 轮。
4. 通过只读 SQLite 连接、authorizer、4 秒执行上限和 100 行返回上限保护数据查询。
5. 将会话记忆与业务数据分库存储，提供浏览器界面展示回答、SQL 依据和历史对话。
6. 建立 12 条基础题和 7 条多表、时间、分母及粒度相关的进阶题，以标准 SQL 对照工具查询结果，并记录执行率、结果匹配率、响应时间和 Token 用量。
7. 加入跨轮追问及破坏性请求场景，验证上下文指代、只读拦截和数据行数不变；据追问失败发现 Agent 多连 payments 导致漏掉无支付记录订单，再补充粒度规则并复跑。

## R：结果

当前回归与场景测试结果：

- 基础题 + 进阶题 SQL 执行率：100%（19/19）
- 标准 SQL 结果匹配率：100%（19/19）；定义为每题至少一次成功的工具查询与标准 SQL 投影一致
- 中位响应时间：8.991 秒；总计 107,303 tokens
- 标准结果中的 123 个字段值全部出现在最终回答文本中（123/123）；这是提及检查，不是语义正确率
- 两轮追问查询结果匹配：2/2；破坏性请求安全检查：1/1；只读 SQL 拦截探针：5/5
- 最终回答完整一致性：未做系统化自动评估；匹配率不代表开放式回答准确率

## 简历项目描述模板

基于 Olist 9 张业务表构建经营分析 Agent，支持自然语言问数、指标口径查询、只读 SQL 执行和会话记忆；通过 SQLite authorizer、查询超时及结果行数限制约束数据访问，建立 19 条业务问题回归集及多轮、安全场景。在当前一轮回归中，SQL 执行率 100%（19/19），每题至少一次工具查询结果与标准 SQL 一致（19/19），中位响应 8.991 秒；另通过 2 轮追问和 5 项只读拦截探针。结果限于自建问题集，回答文本需继续评估。

评估报告位于 `evaluation/results/regression_suite.json`、`evaluation/results/scenarios.json`。结果匹配按工具轨迹内至少一次成功 SQL 查询衡量；差评率题的最后一次辅助查询不匹配，但此前主查询与标准结果一致。应说明基准集为 19 条自建题，结果不代表开放式问题上的整体准确率。
